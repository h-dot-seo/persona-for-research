# Pin and reopen explicit local journey inputs

A complete research journey can require eight JSON artifacts, a selected pattern,
recorded answer review, imported method-application history and an explicit source
selection. Repeating all paths is error-prone. `journey_inputs.py` records those
**explicit choices** in a small local input card, then reopens them with one command.
It never discovers files, chooses a pattern, fills a review, repairs stale bindings
or silently refreshes a changed file.

This is a reproducibility convenience, not approval, source authority, a project
runner or a new persona format. Existing artifact semantics and human-review
requirements remain unchanged. No provider, network or browser is invoked.

## Try the synthetic end-to-end path

First generate the complete existing synthetic example in a new private directory:

```sh
python synthetic_walkthrough.py ../persona-input-demo --candidate-source offline-import --research-journey --recheck-sources --review-method-use --import-method-use --html-review
```

Then use the committed **synthetic-only** selection to pin those exact outputs:

```sh
python journey_inputs.py prepare examples/synthetic-journey-inputs.json --input-root ../persona-input-demo --source-root ../persona-input-demo/synthetic-sources > ../persona-input-demo/input-card.json
python journey_inputs.py inspect ../persona-input-demo/input-card.json --input-root ../persona-input-demo --source-root ../persona-input-demo/synthetic-sources --format html > ../persona-input-demo/bound-review.html
```

That is the existing 39-stage demonstration plus two actual input-card CLI calls.
Open the new HTML yourself. Its complete snapshot matches the direct journey JSON
except for an additional per-file consistency record. Original/reviewed/rejected
histories remain visible, answer review remains deferred, source checks remain
separate, and nothing becomes scientific approval. The sample selection targets
only filenames generated by this exact full synthetic mode. It is not a generic
file-discovery or approval configuration.

Actual-browser visual, keyboard and print QA remains **unverified** because of the
previously documented cloud socket restriction. This increment does not retry or
bypass it. See [local HTML review](LOCAL_HTML_REVIEW.md).

## Make your own explicit selection

```sh
python journey_inputs.py template > new-input-selection.json
```

The template contains `schema`, `pattern_id: null` and every named artifact slot
set to null. Nothing is selected automatically. Fill the pattern ID and the eight
required slots with paths relative to the input root you intend to supply:

- `package`, `patterns`, `context`, `links`, `proposal`, `draft`, `argument`,
  `publication_relations`.
- Optional `declared_review`, `method_applications` and `source_selection` must
  remain explicitly null unless you select their files. They cannot be omitted.

Each non-null path must be distinct, canonical relative POSIX-style JSON such as
`review/answer.json`. Absolute paths, dot segments, traversal, duplicate separators,
backslashes, colons, controls and directional-format characters reject. A component
and its enclosing observation still have distinct evidence references; an input
filename does not change those references. Source and pattern selection are not
inferred from a directory name.

```sh
python journey_inputs.py prepare new-input-selection.json --input-root ../my-review > new-input-card.json
python journey_inputs.py inspect new-input-card.json --input-root ../my-review --format text
```

If `source_selection` is non-null, supply `--source-root` explicitly on **both**
prepare and every later inspect call. If the slot is null, a source-root argument
rejects rather than silently doing something different. The source root is never
saved in the card as an automatic permission. Source selection uses the existing
[local source recheck](SOURCE_RECHECK.md) contract and boundaries.

## What preparation and inspection establish

Preparation preflights the entire named artifact selection, reads bounded current
bytes, parses strict JSON and runs the complete existing journey inspector. It
returns a new card only if those supplied artifacts compose correctly. The card
contains each chosen relative path, byte count, raw-byte SHA-256 and logical-JSON
SHA-256. It stores no command, provider permission, decision override, source root,
absolute input root, cached approval or materialized scientific result.

Inspection first verifies each artifact against the card, then reruns the normal
journey validation with the exact current artifacts. A whitespace-only edit or
line-ending change is a raw-byte mismatch even if the logical JSON is unchanged.
A forged logical digest also fails. Merely editing card hashes cannot repair stale
cross-artifact bindings. Changing a review note, proposal, pattern or context still
requires the appropriate fresh bindings and explicit review, not copied hashes.

To intentionally use changed files, preserve the old card and run `prepare` again
with the explicit selection, saving to a new filename. This creates a new record;
it does not authenticate the changes, migrate old artifacts or approve a method.
A consistently edited unsigned card/history cannot prove who changed or reviewed it.

JSON output is the usual journey result plus `local_input_file_check`, which records
the card hash and each matched artifact. Text adds the same check after the complete
journey review. HTML shows the file-check scope and full per-file records, and retains
all fields in its reversible snapshot. `journey_input_sha256` still binds the logical
journey inputs; the card hash separately binds selected paths and file identities.
The existing inspected-snapshot hash includes the extra file-check record.

Each command invokes the journey once for its chosen format. Requested current
source checks run once per command, not twice for rendering. Running prepare and
inspect separately intentionally checks current source bytes twice. No source check
is implied merely by matching JSON files. Opening a saved report reruns nothing.

A copied set of identical files can be reopened under a different explicitly chosen
input root. The card never reaches outside that selected root to find missing files.
No existing or partial result is overwritten by the tool: output is stdout only.
Shell redirection can overwrite files, so choose new private output paths yourself.

## Filesystem, resource and privacy bounds

- The selection/card file itself must be regular, with no symlink path components,
  and is read through the bounded descriptor reader. FIFOs/devices/directories reject.
- All artifact paths/types are preflighted before reading any artifact bytes. The
  input root and artifact components reject symlinks, and resolution cannot silently
  redirect a path. Descriptor checks detect supported replacement/change cases.
- Keep the selected filesystem stable. These checks are **not** an OS sandbox,
  atomic multi-file snapshot or complete hostile concurrent-filesystem defense.
  No directory-descriptor traversal or persistent lock is claimed. Bound hashes
  still reject mismatched bytes; preparation records the bytes it actually read.
- The artifact no-symlink policy does not redefine original-source path handling.
  Live sources reuse `corpus_files`/source-recheck rules, which can accept symlinks
  resolving within their explicitly selected source root. Source-authentication and
  stable-filesystem limitations remain unchanged.
- Selection/card: at most 128 KiB. All selected artifact bytes combined: at most
  8 MiB, not 8 MiB per slot. Existing journey JSON/HTML/output limits still apply;
  final output is capped at 16 MiB. Live source-byte budgets are separate existing
  source-recheck limits.
- Strict JSON rejects duplicate keys, nonfinite values and excessive nesting.
  Exact schemas reject extra commands, credentials, permissions and cached verdicts.
  Failures return nonzero with no partial stdout result.

Cards and reports may reveal private filenames, identifiers, quotes and annotations.
They are not anonymized or authorized for sharing. The tool neither transmits them
nor saves authentication information. Hash consistency establishes neither meaning,
rights, authenticated review, researcher fidelity nor permission to execute a study.
